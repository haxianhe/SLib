# 角色音频与镜头交接

用于分角色声音、旁白定轴、对唱和声音驱动视频。尊重项目已有格式；仅在实际制作需要落盘时建立 `audio/segments.md`，也可直接在现有清单或对话中维护。不要重复建立内容相同的多份台账。

## 分句与音频记录

为台词／歌词分配稳定句 ID，记录角色、原文、独唱／轮唱／合唱或对白／旁白、情绪与音色版本。区分试音与已选定音频；同一角色换音色也需要新版本。

角色音频与镜头对应表至少包含以下信息，未知值写待定：

| 字段 | 记录内容 |
|---|---|
| 句 ID、角色 ID | 如 line_001、char_lin；合唱时列出所有演唱角色 |
| 内容与形式 | 台词／歌词原文；对白、旁白、独唱、轮唱或合唱 |
| 音色及音频版本 | 音色标识／参考版本、实际选用文件路径及版本；规划路径明确标为计划 |
| 源音频入出点 | 该句在源文件内的起止秒数；未实测标为预排 |
| 成片时间位置 | 在整集时间线的起止秒数；与源文件入出点分别记录 |
| 对应镜头与人物 | 一个句 ID 可对应多个镜头，一个镜头可引用多句；注明需驱动嘴型的画面角色 |
| 依赖与状态 | 是否要求口型／卡点、音频待生成／待试听／已选定、视频使用的音频版本与复核状态 |

时间码以实际音频为准，保留呼吸、停顿和尾音。未定旋律或未获得实际音频时，分句表只是规划，不能算作已按歌曲定轴。

## 对唱与Rap提示词

用于人物轮唱、双声部歌曲或国风Rap的创作提示词，不替代具体产品的输入契约，也不强制所有声音任务使用即梦或某个模型。

### 写法与表演引导

- **先给整体听感：**目标总长、语言、对唱／Rap形式、角色关系、节奏、伴奏与人声主次。只保留会改变听感的场景信息；“压着怒火的君臣交锋”比罗列服装、机位、观众数量更直接。确需现场感时描述少量环境声，不让它盖过歌词。
- **声线要有区别：**分别写年龄感、音域、厚薄、沙哑／清亮、共鸣和说话习惯；再描述冲突中如何变化。避免两位角色都只有“低沉、霸气”。不要求模仿真实演员或歌手。
- **写可表演的情绪：**用情境、重音、停顿和语气转折引导。例如“质问时把字压住，句尾留一口气；对方先冷笑般轻收，再压低声音回应”。比喻可帮助建立听感，但应落到能听见的变化，不堆砌故事梗概或形容词，也不把原创心理当作历史记载。
- **自然交锋，不逐句卡秒：**说明轮流接唱、气口、短暂鼓点回应、情绪升温和结尾回落，让模型按音乐组织长短。分角歌词逐段列出，角色标签不读出；合唱单独标明主次。旋律演唱、Rap、普通朗读分别表述；Rap可以有说话感，验收重点是实际律动、重音与声部，而不是一律要求拖长旋律。
- **控制信息密度：**风格、声线、表演与歌词分段写，避免重复否定、逐字表演命令及一轮叠加过多新目标。对已有满意的音乐与声线，优先保留原描述，只改用户不满意的部分。合唱不达标时核验能力或讨论分轨方案，不默默删除已要求的合唱。

### 时长、音色与实际入口

- **单独强调总时长：**在开头写目标时长，歌词之后另起一行再次明确，例如“注意：生成的音频总时长是15秒，包含演唱、停顿、尾音与伴奏收束。”具体秒数取自当前作品，不能把15秒写死为通用要求。这是总长约束，不等于逐句卡秒；不承诺重复强调就能保证精确输出。
- 保留整段时长目标及必要的入唱／尾声要求，歌词密度应给换气和收尾留空间；默认不要求每句等长，也不把“每句2.7秒”之类预排写成已实现的控制。仅在用户确需固定时码或工具已验证支持时间线编排时使用逐段时间约束，并核对其实际实现方式。
- “完整铺展、交接留气口、最后一句放宽收束”可作为自然表演引导，不能保证精确时长。界面存在时长参数时同步设置；文字写15秒而输出10秒时，先核对实际参数、入口限制和下载文件时长，不只追加“必须15秒”，不靠截尾、重复歌词或极端变速掩盖差异。
- 使用当前入口实际支持的音色引用方式；有 `@` 音色选择时绑定真实选项，不让用户把占位符当作普通文字提交。用户希望文字描述声线且入口支持时可采用描述方式，不强制所有工具都要选内置音色。
- 配音入口标签、模型名字、用户教程与效果满意度分别记录。看到“AI配音”不能证明一定不会Rap，也不能证明支持指定词双人合唱；以真实输出和当前入口能力核验。教程中的准确模型名与功能未经核实不写成通用契约。只借鉴音频提示词时保留其他制作阶段的既定工具和流程。

### 可改写模板

以下为创作简报，角色与歌词需替换为当前项目内容，不是固定输入协议：

```text
[总时长目标]中文[音乐风格]双人[旋律对唱／Rap]，角色甲与角色乙轮流交锋。
[鼓点与伴奏质感]，人声清楚靠前，[直接入唱或所需前奏]。

角色甲的声音：[年龄感、音域、音色特点]。
[说这段话的处境；从开口、重音到句尾如何变化]。

角色乙的声音：[与角色甲可辨的声线差异]。
[回应方式、压抑或爆发的转折，和角色甲形成什么关系]。

两人接唱像过招，给停顿与回应留空间，句子长短随节拍自然变化。
[情绪推进]，最后一句[轮唱／合唱及主次]，完整保留尾音并自然收束。
只使用给定歌词，角色标签不读出。

【角色甲】
[歌词]
【角色乙】
[歌词]
【合唱（如需要）】
[歌词]

注意：生成的音频总时长是[目标秒数]秒，包含演唱、停顿、尾音与伴奏收束。
```

### 生成后校准

先核对真实文件版本、可解码性和实测总长，再试听歌词、发音、两种声线、交接、Rap律动或旋律、合唱与收尾。记录哪些是用户反馈、直接试听或本地测量。ASR只能辅助定位与近音比对，不能单凭转写判定唱错字、声线区分、Rap好坏或合唱完成。

声音通过后才把实际分句与节拍写入角色音频／镜头对应表，调整画面切点与字幕，不反过来逼音频服从旧文字分镜。未完成试听或用户仅报告已生成时，保留候选状态，不自动升为已验收主轨。不为验证改写提示词而擅自重新生成；已有授权和尝试上限继续适用。

## 制作与验收

- **对白／旁白：**检查发音、角色归属、情绪、语速、气口和时长。试音可用于验证剧本是否装得进镜头，最终口型使用选定版本。
- **演唱／对唱：**先确定可用演唱方案，再制作角色声音；分别生成时按同一旋律、调性、节拍和时间轴验收。轮唱检查交接，合唱检查重叠位置及双声部。文本朗读、歌词与伴奏本身不构成歌曲交付。
- **驱动音频：**按实际工具支持的输入形式准备；能提供分角色人声轨时保留它们及最终混音，明确提交的是哪一轨。不默认混合两人声音后工具能自动识别画面中的对应人物；多人同框的角色选择能力未经核验时，先交付可控的单角色片段方案。
- **混音：**保留人声、伴奏和音效的可调整版本，试听人声清晰度、角色响度和尾音，不将某个音量百分比作为统一验收标准。主歌曲通过不代表配音与声音阶段全部通过，仍需检查本集其他必需声音。
- **工具交接：**明确所选入口、输入文件和时间段、目标角色、操作步骤、输出路径及验收方法，并标明谁执行。具体按钮、最大时长、积分与免费额度按当前实际入口核实，不写死社区经验值。长段按分句、呼吸或节拍拆分，兼顾接缝连续性。

## 版本绑定与修改影响

制作声音驱动视频前，记录实际提交的音频版本、源片段、对应镜头和角色。生成记录保留当时输入，后续改选音频不能覆盖该历史记录。若采用先做基础动态、再处理口型的已核实路线，分别记录基础视频与口型处理结果。

| 变化 | 需要复核的范围 |
|---|---|
| 改歌词／台词、音色、语速、分句或人声时间位置 | 重验对应音频；相关口型视频、卡点、字幕及时间线标为待复核；时长或内容改变时再检查相关分镜与画面 |
| 调整伴奏音量，驱动人声和时间位置未改变 | 复核混音及最终导出；无需自动作废口型视频 |
| 调整伴奏节拍或歌曲结构 | 复核受影响的人声对齐、卡点、镜头时点、字幕和剪辑 |
| 更换图片中的角色或人物位置 | 核对声音与画面角色绑定，以及相关视频；不自动作废无关声音 |

“待复核”不等于必须重新生成。先比较实际变化，确需重做时仍在用户已有授权及尝试上限内执行；保留旧候选，不无限重抽。进度卡写明影响的句 ID／镜头 ID、阻塞条件、可并行工作和下一动作。
