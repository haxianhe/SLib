# Search

在网络和工具条件不稳定时完成可追溯检索。核心原则：**先判断数据边界，再逐层降级；访问失败不等于获得绕过授权**。

## 何时不触发

- 用户只要求解释一个稳定概念，且不要求最新信息、来源或联网。
- 用户明确要求不要联网。
- 请求涉及内部资料但没有目标系统、主题或授权范围。

## Step 0：判断查询边界

先区分：

| 类型 | 处理 |
|---|---|
| 公开信息 | 可使用公开搜索和网页读取能力 |
| 用户提供的公开 URL | 直接读取 URL，必要时再搜索替代来源 |
| 登录态或内部资料 | 不把内部关键词发送到公开搜索引擎；先确认系统、账号/工作区、查询范围和允许处理的数据 |
| 凭据、密钥或高度敏感数据 | 不写入查询词、命令、日志或最终报告 |

使用登录态浏览器前，必须说明将访问的域名、使用的身份范围、检索目的和会读取的内容，并取得用户确认。不得默认选择浏览器 profile，不得静默保存或跨任务复用登录 state。

## 分层检索

每层得到足够可靠的信息后立即停止；不要为“多试一种”继续扩散数据。

### Layer 1：当前平台的公开搜索能力

用于发现候选来源。优先官方文档、标准、论文、项目仓库和原始公告。记录标题、URL、发布日期及它支持的结论。

### Layer 2：当前平台的只读网页能力

用于读取已知公开 URL。正文为空、JS 渲染失败或临时网络错误时才进入下一层。

遇到 `401`、`403`、登录页、付费墙、robots/组织策略或明确拒绝时停止；这些不是切换通道继续尝试的信号。

### Layer 3：公开 HTTP 获取

仅对无需登录且组织策略允许的公开 URL，使用环境已有的只读 HTTP 客户端获取页面，并执行以下校验：

- 仅接受 `http://` 和 `https://` 的 HTTP(S) URL；拒绝 `file:`、`data:`、`javascript:` 和其他协议。
- 请求前解析主机和 IP，拒绝回环（loopback）、私有地址（private）、链路本地（link-local）、云元数据（metadata）地址和无法安全解析的目标。
- 每次重定向都重新解析并校验目标；不得只校验第一跳。
- 把连接固定到已验证的公开 IP，保留正确的 Host/TLS SNI，并核验实际 peer IP 仍是该公开地址；若无法保证这些条件，跳过 Layer 3。
- 设置合理超时和响应大小上限，不下载无关附件。

显式内部 URL 不走通用 HTTP 获取流程，应按登录态或内部资料流程确认范围并使用用户授权的受控连接器。不得用任何方式绕过代理、认证、访问控制或企业防火墙。

### Layer 4：浏览器

仅在页面必须执行 JavaScript，或用户已明确授权使用指定登录态时使用：

1. 确认域名、身份和最小访问范围。
2. 只读取完成任务所需的页面或片段，不下载无关附件。
3. 不执行写操作、提交表单、修改设置或扩大共享范围。
4. 除非用户明确要求，不持久化 Cookie、会话或浏览器 state。
5. 任务结束后报告实际访问范围，不输出凭据或敏感正文。

## 结果验证

- 关键结论至少由一个直接来源支持；高风险或有争议结论尽量交叉验证。
- 区分来源事实、作者观点和自己的推断。
- 标注来源日期；对于时效性问题优先最新的一手材料。
- 给出可点击来源，不把搜索结果页当作最终证据。

## 全部失败时

列出尝试过的层级和具体失败原因，例如网络超时、正文为空、需要登录或访问被拒绝。随后提出安全的下一步：请用户提供可访问链接、粘贴正文、缩小查询范围，或确认指定登录态访问。

不得因为工具调用过就声称“已找到”，也不得把 `401/403` 描述为需要突破的障碍。
