# Summary

把可验证的来源提炼成结构化摘要，并按用户意图保存到本地知识库。核心原则：**先取得正文、来源有据、写入前确认**。

## 输入与正文获取

接受两种输入：

- **URL**：使用当前运行环境已有的只读网页访问能力获取正文。
- **文本**：直接使用用户粘贴的正文或上游工作流提供的内容。

处理 URL 时：

1. 仅接受 `http://` 和 `https://` 的 HTTP(S) URL；拒绝 `file:`、`data:`、`javascript:` 和其他协议。
2. 记录原始 URL，并在请求前解析主机和 IP。拒绝回环（loopback）、私有地址（private）、链路本地（link-local）、云元数据（metadata）地址和无法安全解析的目标。
3. 每次重定向都按同一规则重新解析并校验目标；不得只校验第一跳。显式内部 URL 不走通用网页获取流程，应改用用户已授权的内部连接器。
4. 直接 HTTP 客户端只有在能够把连接固定到已验证的公开 IP、保留正确的 Host/TLS SNI，并核验实际 peer IP 仍是该公开地址时才可使用；若无法保证这些条件，跳过直接 HTTP 获取，改用平台提供的受控网页访问能力。
5. 通过校验后再尝试读取公开正文。设置合理超时和响应大小上限，不下载无关附件。
6. 登录墙、付费墙、访问策略或网络错误导致无法读取时，不切换到规避访问控制的方式。
7. 明确说明失败原因，请用户**粘贴正文**或提供可访问版本。
8. 没有正文时停止；禁止依据标题、摘要片段或常识编造文章内容。

## 执行流程

### 1. 确认理解

取得正文后，展示：

- 来源和标题；
- 用户关注角度，未指定时为“全面提炼”；
- 是否保存；
- 目标路径，默认 `~/KnowledgeDB/raw/YYYY-MM-DD-{slug}.md`。

若用户只要求在对话中总结，可先返回摘要而不写文件。任何本地写入前都必须展示解析后的目标路径并取得确认；上游工作流也不得替用户跳过写入确认。

### 2. 选择摘要结构

按正文主要目的选择一种结构，不确定时使用“原理/分析”：

| 类型 | 识别信号 | 核心章节 |
|---|---|---|
| 技术教程 | 步骤、命令、代码、操作指南 | 功能定位、快速上手、关键接口、常见坑、适用场景 |
| 原理/分析 | 架构、设计决策、方案对比 | 核心理念、关键决策、权衡、对比、启发 |
| 行业资讯 | 事件、时间、数据、公告 | 核心事件、时间线、影响、判断、后续信号 |
| 思想观点 | 论点、方法论、个人反思 | 核心论点、论据、启发、局限、一句话总结 |

只保留正文能够支持的章节；不要为了套模板填充空泛内容。关键代码、数字、时间和限制条件应准确保留。

### 3. 判断是否需要图表

仅在可视化能明显降低理解成本时使用 `architecture-diagram`：

- 至少 4 个组件的结构或依赖；
- 至少 3 步的流程或决策分支；
- 跨角色调用时序；
- 多阶段时间线或概念层级。

纯观点、单一概念和简单列表不生成图。图表文件与摘要放在同一目录，正文使用 HTML 注释记录对应 `.drawio` 路径；不要声称已导出 PNG/SVG。

### 4. 写入知识库

文件名使用当天日期和标题 slug。中文标题可以保留，空格改为 `-`，移除文件名非法字符。

```markdown
# {标题}

> **来源** {URL 或出处}
> **日期** {YYYY-MM-DD}
> **类型** {技术教程 / 原理分析 / 行业资讯 / 思想观点}
> **标签** {tag1} · {tag2} · {tag3}  
> **关键概念** {concept1} · {concept2} · {concept3}

---

{结构化摘要}
```

默认目录固定为 `~/KnowledgeDB/raw/`，除非用户在确认时指定其他位置。创建目录和文件后，返回真实路径；写入失败时报告错误，不得声称已保存。

## 质量检查

- 每个判断都能追溯到正文，不补充来源没有的信息。
- 摘要以提炼为主，不逐段复述。
- 引用保持简短，长内容使用转述。
- URL 无法读取时请求正文，不猜测。
- 写入前已确认路径，写入后已核验文件存在。
- 只有确有结构、流程、时序或层级关系时才附图。
